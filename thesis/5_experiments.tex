Из таблицы следует ряд выводов.

Потеря точности при квантизации минимальна: $-0{,}31$~п.п. для PTQ и $-0{,}17$~п.п. для QAT. Оба значения находятся в пределах статистической погрешности, обусловленной конечным размером тестовой выборки. Таким образом, для данной архитектуры и задачи выбор между PTQ и QAT не является критическим с точки зрения точности.

Время инференса PTQ-модели (0,91~мс) ниже, чем QAT (1,34~мс). Различие обусловлено деталями квантизации отдельных слоёв: PTQ-конвертер TFLite оптимизирует диапазоны квантизации для минимизации ошибки, тогда как QAT фиксирует диапазоны, определённые в процессе обучения. Оба значения пренебрежимо малы в сравнении с длительностью полного цикла каскада (3--4~с).

Коэффициент сжатия $3{,}66$--$3{,}67\times$ (вместо теоретических $4\times$) обусловлен наличием метаданных графа, параметров квантизации и служебных структур в формате TFLite.

Расхождение обусловлено токами покоя компонентов обвязки модуля:

	\item линейный стабилизатор напряжения (LDO) модуля: типичный ток покоя LDO семейства AMS1117 составляет 5--10~мА; стабилизаторы с низким током покоя (HT7333, HT7833) обеспечивают 4~мкА, однако на модулях Waveshare используются стандартные регуляторы;
	\item микросхема Flash-памяти (8~МБ): потребление в режиме standby порядка десятков мкА;
	\item микросхема PSRAM (8~МБ): потребление в режиме self-refresh порядка десятков мкА;
	\item преобразователь уровней USB-UART (при наличии): до 100~мкА.
\end{itemize}

На профиле выделяются характерные фазы:

\begin{enumerate}
	\item \textbf{Cold boot} ($t_0$ -- $t_1$): инициализация ядер, загрузка прошивки из Flash; потребление \textbf{[PLACEHOLDER]}~мА, длительность \textbf{[PLACEHOLDER]}~мс;
	\item \textbf{Инициализация I2S} ($t_1$ -- $t_2$): конфигурация DMA-буферов и запуск приёма данных с INMP441;
	\item \textbf{Захват аудио + MFCC} ($t_2$ -- $t_3$): активная работа I2S и вычисление признаков на ЦПУ; длительность $\sim$3~с (окно прослушивания);
	\item \textbf{Инференс DS-CNN} ($t_3$ -- $t_4$): выполнение \texttt{Invoke()} TFLM; длительность $<$2~мс;
	\item \textbf{Возврат в deep sleep} ($t_4$ -- $t_5$): деинициализация I2S, изоляция GPIO, переход в сон.
\end{enumerate}

\subsection{Обсуждение результатов и ограничения}

\subsubsection{Влияние обвязки модуля на энергоэффективность}

Измерения показали, что потребление модуля ESP32-S3-Zero в режиме глубокого сна значительно превышает паспортные характеристики кристалла. Данное расхождение является типичным для отладочных модулей: в литературе и сообществе разработчиков широко документировано, что LDO-стабилизаторы на модулях общего назначения (AMS1117 и аналоги) вносят доминирующий вклад в потребление покоя. Для промышленного применения рекомендуется использование LDO с низким током покоя (HT7333, HT7833 с $I_q = 4$~мкА) или проектирование собственной печатной платы с минимизированной обвязкой.

Тем не менее данное ограничение не снижает ценности полученных результатов: каскадная архитектура обеспечивает кратное снижение среднего потребления по сравнению с always-on режимом на той же аппаратной платформе, и выигрыш сохраняется вне зависимости от абсолютного уровня потребления в deep sleep.

\subsubsection{Ограничения методики измерений}

Период опроса INA228 (200~мс) не позволяет разрешить субмиллисекундные пики потребления (cold boot, инференс DS-CNN $<$2~мс). Для детального профилирования этапа инференса необходим осциллограф с токовым щупом. Вместе с тем для оценки интегрального энергопотребления за цикл данное ограничение не является критичным, поскольку энергия коротких пиков пренебрежимо мала на фоне 3-секундного окна захвата аудио.

\subsubsection{Направления дальнейшего развития}

На основании полученных результатов определены следующие направления улучшения:

\begin{enumerate}
	\item проектирование собственной печатной платы с LDO, имеющим ток покоя $<$10~мкА, для приближения потребления в deep sleep к паспортным характеристикам кристалла (7--8~мкА);
	\item применение MOSFET-ключа для полного обесточивания INMP441 и LM393 в режиме глубокого сна с управлением через RTC GPIO;
	\item сокращение окна прослушивания с 3 до 1--1,5~секунд с использованием скользящего буфера для снижения энергии за цикл;
	\item исследование архитектуры TC-ResNet как альтернативы DS-CNN для дальнейшего сокращения времени инференса;
	\item адаптация системы для русскоязычных голосовых команд с дообучением на соответствующем наборе данных;
	\item верификация каскадной архитектуры на платформах STM32U5 и nRF52840 для подтверждения переносимости подхода.
\end{enumerate}

\subsection{Выводы по разделу}

Экспериментальная апробация подтвердила работоспособность предложенной каскадной архитектуры. Квантизация модели DS-CNN-M до INT8 обеспечивает сжатие в $3{,}67\times$ при потере точности не более 0,31~п.п. и ускорении инференса до 0,91~мс (PTQ). Доминирующим источником энергопотребления в каскадном цикле является этап захвата аудио, а не нейросетевой инференс, что согласуется с данными литературы. Основным ограничением является потребление обвязки модуля в deep sleep, устранимое при переходе к собственному аппаратному дизайну.
